# Shared Verification

Root, after every phase:

```sh
zig build test --summary all
scripts/update-generator-cases.sh && git status --short tests/generator_cases
```

Examples, after phases 2, 3 and 4:

```sh
for example in examples/*; do
  (cd "$example" && zig build test go-check go-lib abi-check go-coverage) || true
done
```

`examples/13-rust-quick-start` takes the Rust step list instead:

```sh
cd examples/13-rust-quick-start
zig build test rust-check rust-lib abi-check rust-coverage
(cd rust && cargo test && cargo clippy --all-targets -- -D warnings && cargo fmt --check)
```

The root build has no `go-check`; those steps exist only in example builds.
`tests/generator_cases/<case>/semantic.json` is the input and the sibling
`expected/` tree is the golden, so a clean regeneration is the regression
suite. Grep `plugins/` as well as `src/` when renaming anything a plugin reads.

# Decisions That Constrain Ordering

Phase 0 and 1 are behaviour-preserving and must leave every golden untouched,
which makes them the safe base. Phase 2 is the only phase that changes
generated bytes, and it adds its coverage before its fix so the change is
visible as a diff rather than asserted. Phase 3 changes neutral code that both
backends run and so wants the emitters already settled. Phase 4 touches build
wiring only and is last because its verification is the slowest.

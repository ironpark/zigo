# Build integration and a runnable example

## Planned Work

- Extract the shared reflector and module-graph setup out of `addGoBindings`,
  with `addGoBindings` calling it. This is the Go-side edit CONTEXT argues for;
  it must be behaviour-preserving, which the thirteen examples check.

  **Divergence: it landed in `build.zig` as a private `addReflection`, not in
  `build/modules.zig` as planned.** `build/modules.zig` would have needed
  `dependencySourceRoots` and `collectDependencySourceRoots` moved with it, and
  those two are already correct in `build.zig` (they carry a visited set for
  diamonds and cycles). Moving them would have widened a behaviour-preserving
  extraction into a relocation. Keeping the helper in the same file leaves them
  in scope and moves nothing.
- Add `addRustBindings` to `build.zig`: the shared reflection and semantic
  capture, `generate --target rust`, the shim static library and header install
  (identical to Go's), publish and `check` over the manifest, and
  `RustBindings.addStandardSteps` registering `rust`, `rust-check`,
  `rust-lib`, `abi-check` and `cargo`-driven `rust-test`.
- `examples/13-rust-quick-start/`, mirroring `examples/00-quick-start`:
  - `src/root.zig` with `add(a, b) -> i32` verbatim from the quick start, plus
    `sum(values: []const i32) -> i64` and `divide(a, b) -> MathError!i32` so the
    three supported shapes are all exercised. No cancellation, no callbacks, no
    handles.
  - `src/bindings.zig` declaring the three.
  - `build.zig` calling `addRustBindings`.
  - `rust/Cargo.toml` and `rust/build.rs`, hand-written, linking the installed
    static archive -- the counterpart of the Go examples' `go.mod`.
  - `rust/src/lib.rs` and `rust/src/raw.rs`, generated and committed.
  - `rust/tests/bindings.rs` covering all three functions -- an integration
    test rather than a `#[cfg(test)]` module, because `src/lib.rs` is
    regenerated by `zig build rust` and a test inside it would be overwritten
    -- and `rust/examples/demo.rs` printing `2 + 3 = 5`.
  - `rust/Cargo.lock` is committed. The crate has no dependencies, but `cargo`
    writes the file and CI's `git status --porcelain` check would otherwise
    call the tree dirty.
  - `README.md` in the shape the other examples use.
- Run it: `cargo test` and the demo, for real. **Actual output, from a removed
  `rust/target` and `zig-out`:**


  `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` are both
  clean. `abi-check` needed the example's first commit before it could pass:
  it reads its baseline with `git show HEAD:./zigo/semantic.json`, which does
  not exist for a brand-new example. Verified immediately after committing.

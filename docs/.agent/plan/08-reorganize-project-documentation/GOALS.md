# GOALS

## Problem and the end result from the user's point of view

The current README mixes the project introduction with detailed configuration, design rationale, ABI behavior, and limitations, while all documents share one flat directory.

## Measurable goals

Move every existing design document into `docs/design/`, reduce README to an overview and quick start, and publish detailed usage and limitations under `docs/wiki/` with working navigation.

## Supported scope and non-goals

Documentation layout, wording, examples, and internal links are in scope. Runtime behavior and public APIs are not changed.

## Reference source / commit / license

Use the current README, documentation, build API, and examples in this repository as the source of truth.

## Completion criteria for the whole plan

The documentation has distinct design and wiki areas, README is concise and introductory, detailed guidance remains discoverable, all relative Markdown links resolve, and retained commands/examples validate against the repository.

# SCOPE

- `src/gen/naming.zig`(또는 적절한 공유 모듈): 함수 export 심볼 규칙 한 함수 `functionSymbolAlloc(prefix, owner, name)`.
- `src/reflect/walk.zig:187`, `src/gen/lower.zig:199-210`, `src/gen/validate.zig:585`: 위 함수를 호출. purego `_purego_v2` 접미는 lower에만 남긴다.
- `src/reflect/names.zig`: doc 수집 규칙 확장(연속 선언 공유, `//` 그룹 주석).
- `src/gen/emit.zig`: `writeGoDoc` 두 줄 형식, 필러 문구 정리, 패키지 doc 출력, `Options.go_package_doc`.
- `build.zig`: `addGoBindings` 옵션 plumbing.
- `tests/godoc_audit/main.go`: 두 줄 형식 허용 유지 확인, 패키지 doc 단정.
- `tests/generator_cases/*`, `examples/*` 골든·`semantic.json` 재생성.

# CONTEXT

## Current implementation and bottlenecks

- 심볼 규칙이 세 곳에 있다: `walk.zig:187`(틀림, snake 변환도 없음), `lower.zig:199-210`(정답: `receiver orelse namespace`, snake, purego 접미), `validate.zig:585 functionSymbolAlloc`(정답, 충돌 검사용).
- `abi_diff.zig:155-170`는 함수를 `name`+`receiver`+`namespace`로 매칭하므로 중복 `symbol`이 매칭을 망치지는 않는다. `:75-76`의 심볼 비교만 무력화된다.
- 주의: `symbol` 정정은 커밋된 모든 `semantic.json`을 바꾼다. `abi-check`가 커밋된 메타데이터와 새 생성물을 비교한다면 "exported C symbol changed"를 breaking으로 보고할 것이다. 이는 메타데이터 오류 정정이지 ABI 변화가 아니므로, 예제 `semantic.json`을 같은 커밋에서 재생성하고 필요하면 `abi_diff`에 "옛 규칙의 symbol → 새 규칙" 1회 이행을 허용하는 방식(예: 옛 JSON의 `symbol`이 새 규칙으로 재계산한 값과 다르지만 owner/name이 같으면 compatible로 취급, 또는 `ir_version` bump)을 택한다. 어느 쪽이든 결정을 문서에 남긴다.
- doc: `names.zig:88`에서 `std.zig.Ast.parse`, `:178`에서 `docCommentAlloc(tree, proto.firstToken())`, `:192-206`은 `.doc_comment` 토큰만 거슬러 읽는다. `//` 주석은 토큰이 없으므로 원본 바이트를 직접 봐야 한다(`tree.tokenStart`/`tokenSlice`로 직전 토큰 끝과 fn 첫 토큰 사이 구간을 스캔).
- `writeGoDoc` `emit.zig:4357-4383`: `withoutLeadingName`(`:4389`)이 이름 중복만 제거, `continuesSentence`(`:4402`)가 첫 글자를 소문자화. 명사구 시작을 감지하지 못한다. 필러 `:4411/:4413`.
- `godoc_audit` `main.go:78-83`: `text == name || HasPrefix(text, name+" ")`. 두 줄 형식(`// Name\n// The …`)은 doc 텍스트가 `Name\nThe …`이므로 `HasPrefix(name+" ")`에 걸리지 않는다 — audit 규칙을 `name` 단독 첫 줄도 허용하도록 바꿔야 한다.
- 패키지 줄: `publicPackageAlloc` `emit.zig:796`, 출력 지점 `:72, 84, 100, 132, 138, 2418, 2676, 2846, 3238`. 메인 공개 파일은 `renderPublic`(`:2418` 부근).

## Target structure and invariants

- 심볼 규칙은 단 하나의 함수에서 나오고, `semantic.json`의 `symbol` == 헤더 export 이름(purego 접미 제외 — 접미는 백엔드 산물이므로 `symbol`에 넣을지 명확히 결정하고 문서화; 권장: 넣지 않고 lower가 붙임).
- doc 수집 우선순위: (1) 선언 직전 `///` 블록, (2) 선언 직전에 빈 줄 없이 붙은 `//` 줄들, (3) 직전 선언과 빈 줄 없이 연속된 `pub fn`이면 직전 선언의 doc 공유. 공유는 같은 컨테이너의 연속 fn 선언에만, 다른 doc이 사이에 있으면 끊는다.
- Go doc 출력: 본문 첫 단어가 Go 이름·Zig 이름이면 접합(현행). 첫 단어가 소문자 동사이거나 대문자+소문자 단어로 `continuesSentence`가 참이더라도 관사·대명사(`The/A/An/This/It/Its/These/Those`)로 시작하면 두 줄 형식 `// Name\n// <본문 그대로>`. 그 외 대문자 시작 문장도 두 줄 형식이 안전하다 — 접합은 "이름으로 시작하거나 소문자 동사로 시작"할 때만.
- 문서 없는 함수의 필러는 유지하되 한 문장으로 사실만: `// Name calls the Zig function Owner.name.` 정도로 정리(현재 문구와 다르면 골든 변경).
- 패키지 doc: `Options.go_package_doc: []const u8 = ""`. 비어 있으면 `bindings.zig`의 최상위 컨테이너 doc(`//!`, `.container_doc_comment` 토큰)을 사용하고, 그것도 없으면 `// Package {name} provides Go bindings generated by zigo.` 기본 문장. 공개 패키지의 메인 파일 한 곳에만 출력. raw 패키지도 같은 규칙으로 한 파일(`// Package raw …`).

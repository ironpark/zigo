# 제약과 리스크

이 문서는 구현자가 지켜야 할 경계를 설명합니다. 사용자에게 보이는 지원 범위와 우회 방법은
[지원 범위와 제한사항](../../limitations.md)을 참고하세요.

## C ABI를 공통 경계로 사용한다

Zig의 내부 호출 규약이나 메모리 표현을 Go에서 직접 해석하지 않습니다. 생성된 Zig shim이
Zig API를 C ABI로 바꾸고, Go의 raw 계층이 그 ABI를 호출합니다. cgo와 purego는 같은 공개
바인딩을 목표로 하지만 호출 방식과 로더 API는 다릅니다.

- 정수·포인터·길이·오류 코드처럼 C로 표현할 수 있는 요소로 낮춥니다.
- 일반 struct의 내부 레이아웃은 공개하지 않습니다. 객체는 handle로, 중첩 결과는
  materialized 버퍼로 전달할 수 있습니다.
- 값 전달은 지원되는 extern struct와 제한된 packed struct에 한정합니다.
- 플랫폼별 라이브러리가 필요합니다. 크로스 컴파일은 지원하지만 타깃에서의 실행 검증을
  대체하지 않습니다.

정확한 타입별 규칙은 [ABI 하강 규칙](03-lowering-rules.md)에 있습니다.

## 메타데이터는 수명 계약이지 구현 검증이 아니다

reflector는 함수와 타입을 읽을 수 있지만 native 함수가 포인터를 보관하는지, 어느 함수로
해제해야 하는지는 추론하지 못합니다. 작성자가 `bindings.zig`에 선언한 소유권·retention·release
정보가 실제 Zig 구현과 일치해야 합니다.

생성기는 누락되거나 모순된 선언을 거부하고 Go handle의 사용 중·닫힘 상태를 관리합니다.
그러나 잘못된 native 구현의 use-after-free, 경계 밖 쓰기나 데이터 레이스를 막아 주지는
못합니다. `Close`는 수명 관리 수단이며 객체의 모든 메서드를 스레드 안전하게 만들지 않습니다.

구체적인 호출자 책임은 [객체 수명](../../bindings-handles.md)과
[문자열과 버퍼](../../bindings-buffers.md)에 정리되어 있습니다.

## Go 포인터를 장기 보관하지 않는다

콜백은 Go 값을 native 메모리에 저장하는 대신 정수 토큰으로 찾습니다. retained 콜백은
owner의 수명에 묶이며 종료 시 새 호출을 막고 진행 중인 호출의 정리를 기다립니다.
호출 중에만 빌리는 버퍼도 native 코드가 호출 종료 후 보관해서는 안 됩니다.

콜백의 동시 호출·재진입 가능성은 라이브러리 작성자가 명시하고 지켜야 하는 계약입니다.
자세한 제약은 [콜백과 오류 처리](../../bindings-callbacks.md)를 참고하세요.

## panic 복구에는 한계가 있다

지원되는 호출 경계는 native panic을 오류로 바꾸지만, 이 경계의 복구는 Zig의
`defer`·`errdefer`를 실행하지 않습니다. 관련 handle은 더 사용하지 않도록 처리하며
destructor 호출도 생략될 수 있습니다. 오류를 돌려줄 수 없는 자유 함수의 panic은
프로세스를 종료할 수 있습니다.

따라서 예상 가능한 실패는 Zig error union으로 표현해야 합니다. panic 복구를 정상적인
자원 해제나 오류 처리 경로로 사용하지 않습니다.

## 생성물과 타깃 검증은 별개다

`go-check`는 커밋된 생성물이 현재 선언과 일치하는지 검사합니다. `abi-check`는 지정한
기준 semantic 문서와의 호환성을 검사합니다. 어느 쪽도 실제 native 구현의 동작을 증명하지
않으므로 Zig 테스트와 Go 통합 테스트를 함께 실행해야 합니다.

reflector는 호스트에서 실행됩니다. 타깃에 따른 표현 차이는 하강과 생성 shim의 레이아웃
검사에서 다룹니다. 한 플랫폼의 테스트 성공을 다른 플랫폼의 실행 보장으로 해석하지 않습니다.

## 변경 시 확인할 리스크

| 변경 | 필요한 확인 |
|---|---|
| 타입 표현·함수 시그니처 | semantic/ABI 테스트, 헤더·shim·Go 스냅샷, ABI diff |
| 소유권·Close·콜백 토큰 | 실패 경로, 중복 종료, 진행 중인 호출, Go 통합 테스트 |
| materialized 레이아웃 | 인코더·디코더 일치, 범위 검사, release 경로 |
| 빌드·설치 경로 | 생성물 최신 상태, 설치 아티팩트, 로더와 플랫폼별 테스트 |
| 지원 범위·공개 옵션 | 사용자 문서, 예제, 진단 메시지의 일치 |

실행 명령과 CI 기준은 [프로젝트 개발](../../development.md)에 있습니다.
